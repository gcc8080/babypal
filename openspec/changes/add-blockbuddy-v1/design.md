## Context

仓库为空壳：全部受版本控制的文件都是 openspec 脚手架与各家 AI 工具的 skill 副本，另有一个 `.fvmrc`。无 `pubspec.yaml`、无 Dart 代码、无 CI workflow。整个应用从零建立。

**约束**：
- 单人开发，工期 1–2 个月（约 6–7 周），有硬性交付日（生日）
- 目标用户是一个不识字、手指精度低、注意力以分钟计的 3 岁儿童
- 完全离线；无广告、无内购、无任何数据上报
- 开发者暂无 Apple 开发者账号
- 美术不能成为瓶颈——没有美术资源，也没有外包预算

**关键设计洞察**：数字、加法、字母、汉字四类内容共享同一个心智模型——组合。`3+2=5`、`C+A+T=CAT`、`木+木=林` 是同一个动作的四种皮肤。因此正确的架构不是五个并列的功能模块，而是**一个积木引擎 + 五层内容皮肤**。这决定了工期分配：引擎阶段的质量对总产出是乘数关系。

## Goals / Non-Goals

**Goals:**
- 一套积木交互语法跑通五个内容域；在一个模块习得的动作在其余模块直接可用
- 内容与代码分离：新增学习内容 = 新增 JSON 包，零代码改动
- 语音可增量替换：TTS 打底保证生日不阻塞，真人语音录一条生效一条，无需重新打包
- 手感优先：挤压回弹、音效延迟、吸附宽容度是 3 岁儿童唯一在意的东西
- 从第一天起就满足 App Store 儿童类目标准，避免日后上架返工

**Non-Goals:**
- 不做账号、云同步、排行榜、社交
- 不做儿童端文字界面（全靠语音 + 动画演示）
- 不做完整 i18n；儿童端零文字，家长端只做中文
- 不追求 UI 测试覆盖率；测试聚焦纯逻辑
- v1 不做家长自定义出题器（评估约 2 天工作量，列入 v1.1）

## Decisions

### D1. 积木引擎自研，不引入游戏引擎或物理引擎

纯 Widget + `Transform` + 手写网格吸附。

**理由**：幼儿要的是「吸附到位」的确定感，不是自由落体。引入 Flame/物理引擎后，布局、无障碍、文本渲染、热重载全部要绕路，调试复杂度上一个数量级，换来的能力这个产品一项都用不上。

**备选**：Flame（2D 游戏引擎）——放弃，理由同上；Flutter 官方 `Draggable`/`DragTarget`——部分复用其手势思路，但不直接使用，因为它的命中判定基于组件边界，无法表达「宽容半径」与「吸附到最近合法格位」这两个核心行为。

### D2. 「拖拽」与「点两下完成」双通道必须在引擎层实现

`BlockBoard` 同时暴露两条输入路径：拖拽落子，以及「点积木进入选中态 → 点目标位落子」。任何内容模块都不得只实现其中一条。

**理由**：3 岁儿童的拖拽成功率不稳定——手指离屏、多指干扰、中途松手都很常见。「拖不动」不等于「做不到」，若只有拖拽，挫败感来自操作而非认知，这与「无挫败」红线直接冲突。

**为什么放在引擎层而不是各模块**：这是全局不变量。五个模块做完再回头补，等于改五遍手势逻辑和五套选中态视觉，且必然出现行为不一致。P1 定型是唯一成本可控的时机。

### D3. 触控红线拆成两个阈值，而非单一的 90dp

- **可拖拽积木与按钮：≥ 90dp**——手指要*抓住*的东西
- **放置区（drop zone）：区域制，≥ 60dp，吸附半径 = 目标尺寸 × 1.5**——手指只需*落在附近*

**理由**：单一 90dp 阈值与百格板几何冲突。手机横屏短边约 360dp，扣掉安全区可用高度约 320dp，10 行 → 每格 32dp，不可能满足 90dp。但这不意味着百格板做不了——它意味着**不能要求孩子点中单格**。

**据此重新设计百格板**：孩子拖动的是 ≥90dp 的「十条」或单块，落点是整片棋盘区域，由引擎吸附到正确格位；棋盘本身是展示面 + 渐进填充动画。同理，任何 UI 都不得把小于 90dp 的元素作为**主动操作对象**。

阈值写入 `lib/core/design/tokens.dart`，全局强制。设计基准取短边 360dp，缩放因子 = `MediaQuery.shortestSide / 360`，手机与平板共用一套横屏布局。

### D4. 全链路音频统一 WAV（22.05 kHz / 单声道 / 16-bit）

**理由**：`flutter_soloud` 只支持 MP3 / WAV / OGG / FLAC，**不支持 AAC/M4A**。同时 `record` 的 opus 输出在 iOS 上是 CAF 容器，官方文档明确「playable only on iOS platforms」，跨端不可用。两个约束求交集后，WAV 是唯一在「录制端跨平台可写」与「播放端可读」上都成立且实现最简的格式——`record` 的 wav 编码由 package 自身实现，不走平台编码器，行为最可预测。

**体积**：400 条 TTS × 约 1.5s ≈ 26 MB。对一个离线个人应用完全可接受，且 WAV 解码延迟最低，直接服务于「触摸必有回应」。

**备选**：OGG——体积小一个数量级，但要求本机装 ffmpeg，且家长端录音无法直接产出。折中方案：`voice_resolver` 的扩展名抽成常量，日后若需压体积，加一步离线 ffmpeg 转码即可切换，不动调用方。

### D5. 语音覆盖层：文档目录优先，assets 回落

```dart
Future<String> resolve(String key) async {
  final override = '${docsDir.path}/voice_overrides/$key.wav';
  if (await File(override).exists()) return override;  // 家长录音，录完即生效
  return 'assets/audio/$key.wav';                       // TTS 打底，打包时就在
}
```

**理由**：真人语音（尤其家人称谓和孩子的名字）对情感价值贡献极大，但录 400 条不现实，也不能成为生日交付的阻塞项。覆盖层把「录音」从发布流程里彻底解耦：TTS 保证功能完整，真人语音录一条替换一条，永远不需要重新打包。

生日前优先录约 40 条：家人称谓、孩子名字、鼓励语、生日彩蛋台词。其余 360 条长尾由 TTS 承担。

**健壮性**：override 文件损坏或读取失败时必须回落到 assets，绝不能表现为「没声音」——静默是 3 岁用户无法理解的失败模式。

### D6. 表情与动画用 `CustomPainter` 程序化绘制，不用 Rive/Lottie

积木的脸（眨眼、挤压回弹、张嘴）由 `CustomPainter` + `AnimationController` 绘制。

**理由**：几何积木风格与程序化绘制天然一致；零素材、零依赖、零许可问题；参数化后表情可由内容包驱动。引入 Rive 意味着引入一套外部编辑器工作流，对单人项目是净负担。

名词图标是唯一的例外——用 OpenMoji SVG 子集（约 150 个），因为「苹果」「鳄鱼」这类具象图形无法程序化生成。

### D7. 时长上限用墙钟时间戳，不用 `Timer`

`WidgetsBindingObserver` 监听生命周期，在 `paused` / `resumed` 切换点用墙钟时间戳累加当日已玩时长，持久化到 `shared_preferences`。

**理由**：App 切后台时 `Timer` 会被暂停或杀死。若用 `Timer` 计时，孩子切出去再切回来即可重置额度，功能形同虚设。

达到上限时的表现是**积木「困了」+ 温柔谢幕动画**，不是硬锁屏——目标是让孩子接受结束，不是强制中断。

### D8. 状态管理用 riverpod，存档用 shared_preferences

`flutter_riverpod ^3.3.2`，不用 codegen（`riverpod_generator`）——本项目 provider 数量有限，codegen 带来的构建步骤与心智负担不划算。注意 riverpod **3.x 的 `Notifier` / `Ref` API 与 2.x 有别**，不要照抄旧教程。

存档用 `shared_preferences` + JSON 字符串，不用 Hive/Drift：数据量是「哪些内容练过几次」量级，引入嵌入式数据库要付出 codegen 与 schema 迁移成本，收益为零。

### D9. Flutter 固定 3.44.8，`pubspec.lock` 入库

`.fvmrc` 由 `3.27.4` 升到 `3.44.8`（当前 stable，Dart 3.12.2）。

**理由**：3.27.4 是 2025-02 的版本，本项目选用的 7 个依赖**最新版全部要求更高的 SDK**，锁在 3.27.4 会把整套依赖拽回一年前（`flutter_soloud` 3.5.4 而非 4.x、`record` 6.2.1 而非 7.x、`riverpod` 2.6.x 而非 3.x）。空仓库从零起步，此时升级零成本，日后再升要还技术债。

同时从 `.gitignore` 移除 `pubspec.lock`——这是**应用**不是 library，锁文件必须入库，否则 CI 与本机会解析出不同的依赖版本组合。

`record 7.x` 要求 **Android minSdk 23**，须在 `android/app/build.gradle.kts` 显式设置（Flutter 默认值低于此）。

### D10. 横屏锁定三重保险

`SystemChrome.setPreferredOrientations`（仅横屏）+ Android manifest `android:screenOrientation="sensorLandscape"` + iOS `UISupportedInterfaceOrientations` 只留横屏两项。

**理由**：拼搭需要横向空间；孩子看动画时习惯横持设备；手机与平板共用一套横屏布局，省去约 25% 的适配工作量。三处都设是因为单靠 Flutter 侧 API 在部分 Android 定制系统与 iPad 多任务场景下不可靠。

### D11. 零网络依赖是合规策略的核心

不申请网络权限，不引入任何第三方 SDK，无 IDFA、无埋点。麦克风权限仅用于家长录音与吹蜡烛，且两者都有无麦降级路径。

**理由**：这不只是隐私洁癖——它把 App Store 儿童类目的隐私问卷压缩成一句「不收集任何数据」，把整个合规审查从「需要论证」变成「无从质疑」。零成本，现在做。

### D12. 版权：借鉴机制，原创外观

教学法（立方体表数量、位值、Base-10 blocks / Cuisenaire 数棒）属公共领域，可自由使用。角色形象、配色方案与「Numberblocks / 数字积木」名称受 BBC/Blue Zoo 保护。

**执行红线**：原创角色造型与配色；不使用「Numberblocks」「数字积木」作为 App 名或任何角色名。

OpenMoji 为 CC BY-SA 4.0，义务是**署名**且**图形衍生作品同协议共享**——需在家长区提供署名页，并在 `assets/icons/` 下保留 LICENSE 文件。

## Risks / Trade-offs

**[iOS 免费签名 7 天过期] → 把 Android 设备定为生日交付目标。** 无开发者账号时用免费 Apple ID personal team 可侧载真机，但证书 7 天失效——生日当天装好，一周后孩子就打不开了。Android 侧载无此约束。iOS 侧保持「模拟器可跑 + CI 免签名可编译」，等有账号再上真机。**此取舍影响 P6 在哪台真机上调手感，需在 P0 结束前确认目标设备。**

**[引擎阶段超期拖垮全局] → P1 只做引擎，绝不夹带内容模块。** P1 是乘数项，也是唯一的单点依赖。若 P1 拖期，后续五个阶段同时受阻。宁可 P1 多花两天，也不要带着不稳的引擎进 P2。

**[内容生产（400 条音频 + 150 个图标）挤占开发时间] → 做成离线批处理工具，与开发并行。** `tool/gen_audio.dart` 与 `tool/fetch_openmoji.dart` 在 P1 期间跑完，不占关键路径。真人录音在 P4 之后开始，只需 40 条。

**[范围超出 6–7 周] → 预先约定砍单顺序。** 从先砍到后砍：家长看板 → 反义词跷跷板 → 大小写配对 → 百格板。**绝不砍**：积木引擎手感、生日彩蛋、家人相册——这三项决定这份礼物是「一个 App」还是「爸爸做的东西」。

**[做出来孩子不玩] → 验收标准定在行为而非功能。** 三个指标：他不需要解释就知道该干什么；他主动重复玩同一个模块；15 分钟结束时他抗拒停止（但谢幕动画能让他接受）。任一不达标，**砍功能不如打磨手感**——挤压回弹、音效延迟、吸附宽容度是 3 岁儿童唯一在意的东西。

**[本容器无 Flutter 工具链] → 代码阶段的验证在用户本机或 CI 执行。** 规划阶段不受影响；P0 起 `flutter analyze` / `flutter test` 需在装有 fvm 的环境运行，CI 承担回归职责。

## Migration Plan

无迁移——全新工程，无既有用户与数据。

发布路径：本机 `fvm flutter run` 调试 → Android 真机侧载（生日交付）→ iOS 模拟器与 CI 免签名构建（能力保留）→ 日后取得开发者账号后按已预先满足的儿童类目标准提审。

回滚策略：生日前在 Android 设备上保留上一个可用 APK；每个阶段结束打一个 tag，出问题可回到上一阶段的可玩版本。

## Open Questions

1. **生日交付的目标设备是 Android 还是 iOS？** 影响 P6 手感调优的真机选择与 iOS 签名安排。建议 Android，需确认。
2. **孩子的名字与家人称谓清单**——生日彩蛋（拼名字动画）与优先录音的 40 条依赖此清单，需在 P4 前提供。
3. **家人相册的照片来源与数量**——P6 依赖，需在 P5 结束前提供。
4. **`build/promt.md`（需求原文）** 因 `.gitignore` 忽略 `build/` 而不在版本库中，仅存于开发者本机。若要保留，应迁至 `docs/requirements.md`。
